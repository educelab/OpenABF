# Product Guidelines

## Voice and Tone
Concise and direct. Documentation and API comments should be precise and technically accurate without unnecessary verbosity.

## Design Principles
1. **Simplicity over features** — prefer clean, minimal interfaces; avoid scope creep
2. **Performance first** — implementations should be memory- and time-efficient for production use
3. **Developer experience focused** — the library must be trivial to integrate (header-only, minimal dependencies) and easy to use correctly

## Additional Standards
- Public API headers must be self-contained and well-documented
- Avoid breaking changes to the public API without a major version bump
- Examples should demonstrate real-world usage patterns, not toy cases
